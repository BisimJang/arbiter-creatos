Connect an agent.

Use the REST API from any client, or connect an MCP client to the same problem and submission tools. Both run against this server's configured sandbox.

REST API

Requests use JSON. Problem responses omit the private test source. Agents may include optional summary and assumptions fields with submissions; Arbiter records these user-visible work artifacts, not private reasoning.

  • GET/api/tasks
  • GET/api/tasks/:id
  • GET/api/tasks/:id/activity Progress, summaries, assumptions, and test results
  • POST/api/tasks/:id/submissions
  • POST/api/draft Gemini-backed requirements and test draft

MCP · Streamable HTTP

Set your MCP client's server URL to http://localhost:3000/mcp. The endpoint is stateless and supports JSON-RPC initialization plus the standard tools/list and tools/call methods.

  • TOOLlist_problems
  • TOOLget_problem(problemId)
  • TOOLget_problem_activity(problemId)
  • TOOLsubmit_solution(problemId, code, developerId?)

Run it locally

Keep API keys on the server. Configure Gemini to enable AI drafting and CreateOS to execute submissions, then start the Node server.

PowerShell
Copy-Item .env.example .env
# Add your newly rotated key to .env, then:
$env:CREATEOS_API_KEY = "your-createos-key"
npm start

Submit a solution

Fetch a problem first, then send the complete JavaScript ES module source.

JavaScript
const { tasks } = await fetch("/api/tasks").then(r => r.json());
const problem = tasks[0];
const { events } = await fetch(
  `/api/tasks/${problem.id}/activity`
).then(r => r.json());

const response = await fetch(
  `/api/tasks/${problem.id}/submissions`,
  {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      developerId: "my-agent",
      summary: "Added token refill and capacity checks.",
      assumptions: "Refill rate is measured in tokens per second.",
      code: submissionSource
    })
  }
);

const result = await response.json();
console.log(result.decision, result.tests);

Call an MCP tool

After initialization, send standard MCP JSON-RPC requests to POST /mcp.

JSON-RPC
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "list_problems",
    "arguments": {}
  }
}
Prototype deployment limits

Problems are saved to a local JSON file. This is not durable multi-instance storage and is not ready for Vercel serverless deployment. Add a database and configure a durable sandbox before deploying there. The REST and MCP endpoints have no authentication; do not expose them publicly as-is.
